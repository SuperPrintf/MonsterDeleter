# 原项目审查结论

审查副本：`C:\Users\JLC\Desktop\row`（通过 WSL 静态检查）。

## 需修复的问题

1. `main.py` 在无参数启动时仍会注册右键菜单并打开全屏删除界面；这既不是安装流程，也可能造成意外资源占用。
2. 菜单只写入 `HKCU`，仅当前用户可见；没有卸载逻辑，也没有管理员安装机制。
3. 两个“确认”按钮都进入删除路径，没有“取消”按钮；代码也未处理 `Esc`，用户无法在动画中撤销。
4. `send2trash` 失败仅打印错误。打包为窗口程序后用户看不到错误，也不会得到提权提示。
5. 未校验命令行目标是否存在、是否为文件/目录，且未向用户显示最终操作结果。
6. 每次重绘遮罩时重复从磁盘读取并缩放背景图片；每次播放精灵图都会重新解码全部帧。`assets` 约 25 MB，其中单张爆炸精灵图约 13 MB，属于显著的启动与内存压力来源。
7. `register_menu.py` 与 `main.py` 的注册表写入逻辑重复；`scripts/`、`tests/` 均为开发期图像处理或 UI 自动化试验代码，不应进入运行时安装包。
8. `tests/mouse_tracker.py` 会持续监听全局鼠标输入并把坐标写入临时目录；它不应作为产品功能或随安装包发布。

## 重构后的安全约束

- 仅在右键命令传入明确目标时才执行删除流程。
- 删除前使用模态确认；默认取消，按 `Esc`、关闭窗口或选择“否”均不产生文件操作。
- 仅调用 Windows 回收站删除接口，绝不使用不可恢复的永久删除。
- 遇到拒绝访问时才二次询问，并通过 Windows `runas` 触发标准 UAC 提示；用户拒绝 UAC 即终止。
- 安装包使用管理员权限写入 `HKLM\Software\Classes`，使全部用户可见；卸载程序删除相同键。
